## 1. Auditoría manual de la GUI

### 1.1 Objetivo

Validar de punta a punta la composición de la GUI que ya está cubierta por
tests automáticos y por el camino de datos del CLI/API, pero que necesita
interacción real:

1. Confirmar que el wizard crea un source group Odin correcto y que el
   `.srctrlprj` guarda el tipo estable `odin_empty`.
2. Confirmar que el proyecto indexa los números esperados y sin errores.
3. Confirmar que los menús, las preferencias y el wizard se construyen desde
   los registros reversibles del plugin `ui` (doc 31), sin acciones faltantes
   ni referencias nulas.
4. Revisar el comportamiento visual/interactivo que no cubre el smoke
   offscreen: orden de menús, diálogos, foco, layout y persistencia.
5. Registrar cualquier desviación con captura y log para abrir un fix.

### 1.2 Precondiciones

- Build desktop (`BUILD_GUI=ON`):

  ```powershell
  cmake --build build --config Release --target Sourcetrail
  ```

- Proyecto de prueba: `bin\app\user\projects\odin-sample\odin-sample.srctrlprj`
  (el wizard puede crear uno nuevo).
- Fuentes del sample: `bin\app\user\projects\odin-sample\src`.

### 1.3 Checklist

| # | Paso | Resultado esperado |
|---|---|---|
| 1 | Abrir `Sourcetrail.exe`, `File > New Project` | Aparece el wizard sin errores |
| 2 | En el wizard elegir **Odin** y apuntar a `bin\app\user\projects\odin-sample\src` | El listado incluye Odin con su icono/descripción; el contenido del wizard corresponde a un source group vacío de Odin |
| 3 | Guardar el proyecto y abrir el `.srctrlprj` | Contiene `<type>odin_empty</type>` (no el nombre de display legado) |
| 4 | Indexar (`Project > Refresh` o el botón de indexado) | Termina con **32 nodos / 42 aristas / 0 errores** |
| 5 | Abrir `Edit > Preferences` | Aparecen las páginas: preferencias core, header search global y, en macOS, framework search global |
| 6 | Revisar los menús `Project`, `Edit`, `View`, `History`, `Bookmarks`, `Help` | Cada uno tiene sus acciones; no hay menús vacíos ni entradas duplicadas |
| 7 | Abrir el submenú `Recent Projects` | Lista los proyectos recientes existentes y abre el elegido |
| 8 | Probar `View > Show Title Bars` y los toggles de vistas (dock) | Cambian el layout y el check del menú; no hay crashes |
| 9 | Navegar un símbolo desde la vista de código y volver con History | La navegación y el historial funcionan |
| 10 | Cerrar y reabrir la aplicación | El proyecto, las preferencias y el layout persisten |
| 11 | Repetir la apertura de `main.greet` desde el código y desde el grafo (varias veces) | No debe cerrarse; el crash de purecall quedó corregido en `eca6b558` (doc 36, 1.7) |

### 1.4 Qué NO cubre esta pasada

- El refresco vivo de menús al descargar el plugin `ui`: el plugin es
  `unloadable=false` y no hay un disparador de runtime en producción. La
  notificación del registro está probada en `UiRegistryTest`; el refresco de
  páginas de preferencias se aplica al reabrir el diálogo, que es modal.
- El refresco de una ventana de preferencias ya abierta.
- La composición de perfiles runtime más allá de
  `SOURCETRAIL_DISABLE_PLUGINS`.

### 1.5 Evidencia a registrar

- Captura del wizard con Odin seleccionado.
- Contenido del `.srctrlprj` (bloque del source group).
- Salida del indexado (los tres números).
- Captura de Preferences y de cada menú.
- `error.log` o consola si algo falla.

## 2. E5: build y validación ARM64

### 2.1 Estado

E5 **no se ejecutó** en este fork: el host de desarrollo es Windows x64 y no
hay ninguna máquina ARM64 ni `aarch64-linux-gnu-gcc`. Queda asignado a un
desarrollador con hardware ARM64 (o QEMU/placa). No es un pendiente activo de
este fork.

### 2.2 Artefactos ya preparados

- `vcpkg-triplets/arm64-linux-embedded.cmake`: arquitectura `arm64`, Linux,
  librerías estáticas, CRT dinámico (glibc), Release.
- `vcpkg-triplets/x64-arm64-linux-windows-osx-static-md.cmake`: triplet
  unificado usado por los presets de vcpkg.
- `cmake/toolchains/aarch64-linux-gnu.cmake`: `aarch64-linux-gnu-gcc/g++`.
- `BUILD_EMBEDDED.md`, sección **Cross-compiling for ARM64 Linux**, con el
  comando completo.
- `CMakePresets.json`: presets `vcpkg-*` con el triplet unificado y
  `VCPKG_OVERLAY_TRIPLETS`.
- `docs/Claude-Code/19_cierre_e5_2026-10-18.md`: detalle original del cierre.
- `docs/Claude-Code/25_handoff_2026-10-19.md`: contexto de handoff.

### 2.3 Precondiciones

- Host Linux (o Windows con cross compiler) con `aarch64-linux-gnu-gcc/g++`.
- vcpkg con el overlay de `vcpkg-triplets`.
- Para ejecutar en placa/QEMU: imagen ARM64 con glibc compatible.
- Para indexar Python: runtime Python con `jedi`, `parso` y `numbat`, o usar
  `SOURCETRAIL_PYTHON_SHALLOW=1` / pre-indexar en desktop y copiar el
  `.srctrldb`.

### 2.4 Pasos

```powershell
cmake -B build-arm64 -S . `
  -DCMAKE_TOOLCHAIN_FILE="<VCPKG_ROOT>/scripts/buildsystems/vcpkg.cmake" `
  -DVCPKG_CHAINLOAD_TOOLCHAIN_FILE="cmake/toolchains/aarch64-linux-gnu.cmake" `
  -DVCPKG_TARGET_TRIPLET=arm64-linux-embedded `
  -DVCPKG_OVERLAY_TRIPLETS="vcpkg-triplets"

cmake --build build-arm64 --config Release --target sourcetrail_cli --parallel
```

Luego:

1. `file build-arm64/.../sourcetrail_cli` debe reportar `ARM aarch64`.
2. Copiar el binario y sus datos a la placa/QEMU.
3. Indexar el sample Odin: esperado **32/42/0**.
4. Ejecutar el CLI con un proyecto Python: esperado el baseline de
   `tutorial-py` (103/281/0 con el checkout actual; el número de aristas puede
   variar unas pocas entre corridas, sin errores).
5. Si se compila el perfil desktop, ejecutar la GUI offscreen y el wizard.

### 2.5 Criterios de aceptación

- El binario ARM64 se ejecuta en la placa/QEMU.
- Sample Odin 32/42/0.
- Python completo 103/281/0 (o shallow 100/187/0) sin errores.
- No hay crashes ni dependencias faltantes.
- Se documentan las diferencias de versión de glibc/Qt/LLVM y cualquier
  limitación del entorno.

### 2.6 Fuera de alcance

- LLVM/Clang y la GUI Qt en ARM64 no son necesarios para el perfil embedded;
  si se intentan, requieren build nativo o cross-toolchain con sysroot Qt.
- E5 no bloquea la entrega actual.

## 3. Defectos de Odin detectados por el parser

### 3.1 Resumen

En el checkout de Odin usado para la auditoría
(`<STUDY>\Odin`, commit `c6e2f0b` del 2026-10-18), el indexador reporta **2
referencias no resueltas**, ambas al mismo símbolo:

```text
core/math/linalg/general.odin:1193:14  linalg.matrix_inverse_generic
core/math/linalg/general.odin:1200:14  linalg.matrix_inverse_generic
```

No es un defecto del parser: `matrix_inverse_generic` **no existe** en ningún
archivo del checkout. Un `grep -rn "matrix_inverse_generic"` sobre todo
`<STUDY>\Odin` sólo devuelve esas dos llamadas.

### 3.2 Contexto

Las dos llamadas están en `matrix_pseudo_inverse`:

```odin
// Overdetermined (tall)
AtA_inv := matrix_inverse_generic(AtA) or_return

// Underdetermined (wide)
AAt_inv := matrix_inverse_generic(AAt) or_return
```

Las funciones de inversión que sí existen en el paquete son:

- `matrix_inverse_gauss_jordan`
- `matrix_inverse_lu_decomposition`

Ambas devuelven `(b, non_singular)`; `matrix_inverse_generic` no está definida
ni como alias ni como proc group.

### 3.3 Impacto

- El parser de Sourcetrail no puede resolver las dos referencias y las marca
  como `unsolved` sólo cuando se ejecuta con `--unsolved` (por defecto están
  apagadas).
- El resto de `core` está cubierto: **1.366 archivos, 133.441 nodos,
  356.762 aristas, 0 errores** con `--unsolved`; las 2 no resueltas son estas.
- Para código Odin válido, la cobertura del parser está completa; el problema
  es del fuente de `core`.

### 3.4 Fix sugerido para Odin upstream

Dos opciones, a validar por el mantenedor:

1. **Usar una función existente** en `matrix_pseudo_inverse`, manejando el
   `non_singular`:

   ```odin
   AtA_inv, ok := matrix_inverse_gauss_jordan(AtA)
   if !ok { return }
   ```

   (o `matrix_inverse_lu_decomposition`, según el comportamiento numérico
   deseado).

2. **Definir el alias/proc group** que el código espera:

   ```odin
   matrix_inverse_generic :: proc{
       matrix_inverse_gauss_jordan,
       matrix_inverse_lu_decomposition,
   }
   ```

   Sólo si la semántica de selección coincide con la intención original.

No se debe silenciar la referencia en el parser: señala un símbolo realmente
inexistente.

### 3.5 Reproducir

```powershell
# Indexar un archivo con referencias no resueltas visibles
SourcetrailOdinIndexer.exe index `
  --source-file-path=<STUDY>\Odin\core\math\linalg\general.odin `
  --database-file-path=<STUDY>\odin-linalg.srctrldb `
  --unsolved --debug-refs

# O el core completo en lotes de 128 con --unsolved; el resultado actual es
# 2 referencias (source_location type 9 = UNSOLVED).
```

Ver también `docs/Claude-Code/32_parser_odin_cobertura_2026-10-19.md` y
`34_builtins_odin_2026-10-19.md` para el historial de cobertura y los builtins
que se corrigieron en el parser.
