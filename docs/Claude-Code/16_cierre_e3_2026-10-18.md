## 1. Diseño

`run.py` ahora tiene dos modos:

- **Cliente liviano**: no importa jedi/parso/numbat; solo stdlib. Resuelve rutas y envía
  el request a un daemon.
- **Daemon por base** (`run.py --serve <db>`): mantiene los imports y las cachés de jedi
  calientes, escucha en un named pipe (Windows) o Unix socket (POSIX) derivado del hash
  de la base, y procesa un request por conexión.

Detalles:

- Un daemon por base/thread (los threads de C++ usan bases `_threadN` distintas).
- **La base se abre y cierra por request.** Es deliberado: el daemon original la
  mantenía abierta y el merge/swap de C++ no podía renombrar las bases temporales; la
  base final quedaba **sin tabla `node`**. Abrir/cerrar por request preserva la
  corrección y deja calientes los imports (donde está la mayor parte del ahorro).
- Timeout de inactividad (`SOURCETRAIL_PYTHON_DAEMON_IDLE`, default 60 s) con watchdog.
- Fallback al indexado local si el daemon no arranca o no se puede conectar; los errores
  de indexado no se reintentan (evita duplicados).
- `SOURCETRAIL_PYTHON_DAEMON=0` desactiva el daemon.
- `SOURCETRAIL_PYTHON_DAEMON_DEBUG=1` loguea direcciones/conexiones a stderr.
