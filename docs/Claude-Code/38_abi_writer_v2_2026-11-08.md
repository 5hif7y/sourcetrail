# 38. ABI v2 del writer de SourcetrailDB

**Fecha:** 2026-11-08
**Rama:** `feat/ABI-writer-v2`
**Plan:** es el paso 1 de los cuatro del estudio de Rust y C#:

1. ABI v2 del writer.
2. Convertidor de SCIP a `.srctrldb`.
3. Rust y C# por SCIP.
4. Las bases para tener indexadores propios.

## Para qué

`src/odin_writer` es una ABI de C sobre `SourcetrailDBWriter`. Cualquier lenguaje que pueda llamar
a C la usa para escribir una `.srctrldb`: Odin por `foreign import`, Rust con `extern "C"` y C#
con P/Invoke. Con la v1 alcanzaba para Odin, pero no para lenguajes con sobrecargas o con
dependencias externas, por dos motivos:

- **Sin firmas:** el nombre solo se partía por el separador. `F(int)` y `F(string)` terminaban en
  el mismo nodo.
- **Todo explícito:** cada símbolo quedaba como definido en el proyecto. Los de `std`, NuGet o los
  crates aparecían como propios en lugar de como no indexados.

## Qué agrega la v2

La v1 no cambia: son las mismas 16 funciones, con el mismo comportamiento. Lo nuevo está en
`sourcetrail_odin_writer.h`, después de la marca `ABI v2`.

| Función | Para qué |
| --- | --- |
| `sodb_abi_version()` | Devuelve `2`. Sirve para que quien llama compruebe si tiene la v2 |
| `sodb_symbol_ex(w, delim, elems, n, kind, def)` | El nombre como niveles `{prefijo, nombre, postfijo}`. El tipo de definición es `NONE`, `IMPLICIT` o `EXPLICIT`, y el tipo de símbolo puede quedar sin fijar (`SODB_SYMBOL_KIND_NONE`) |
| `sodb_symbol_signature_location` | El rango de la firma |
| `sodb_qualifier_location` | El calificador: la `Foo` de `Foo::bar()` |
| `sodb_reference_ambiguous` | Marca como ambigua una referencia |
| `sodb_local_symbol`, `sodb_local_symbol_location` | Locales. El nombre es la identidad, así que tiene que ser único, por ejemplo `<archivo>:<línea>:<columna>` |
| `sodb_atomic_source_range` | Un rango que el visor de código no corta, como un comentario de varias líneas |

Además:

- **Constantes:** `SODB_SYMBOL_*`, `SODB_REFERENCE_*` y `SODB_DEFINITION_*`, con los mismos
  valores que los enums de SourcetrailDB. Lo comprueba un `static_assert`.
- **Errores:** si los argumentos son inválidos, la llamada devuelve `0` y no escribe nada. El motivo
  queda en `sodb_last_error()`. Cada llamada borra el mensaje de la anterior.
- **Import y export:** el header importa las funciones (`dllimport`), salvo que esté definido
  `SODB_BUILDING`. Así un llamador en C o C++ puede enlazar contra la biblioteca. Odin enlaza la
  `.lib` directamente y no se ve afectado.

Ejemplo de dos sobrecargas:

```c
sodb_name_element f_int[2] = {{NULL, "C", NULL}, {"void", "f", "(int)"}};
sodb_name_element f_str[2] = {{NULL, "C", NULL}, {"void", "f", "(string)"}};
int a = sodb_symbol_ex(w, "::", f_int, 2, SODB_SYMBOL_METHOD, SODB_DEFINITION_EXPLICIT);
int b = sodb_symbol_ex(w, "::", f_str, 2, SODB_SYMBOL_METHOD, SODB_DEFINITION_EXPLICIT);
/* a != b. srctrl las muestra como C::f(int) y C::f(string). */
```

## Arreglos del SourcetrailDB vendorizado

Los dos están documentados en `vendor/sourcetrail-db/README-VENDOR.md`.

- **`recordReferenceIsAmbiguous`:** devolvía `false` aunque hubiera grabado la marca. Ahora devuelve
  `true`.
- **El tipo de definición:** se guardaba con `INSERT OR IGNORE`, así que el primero que se grababa
  quedaba fijo. Ahora es `INSERT OR REPLACE`, como dice su header. Un símbolo que primero aparece
  como referencia implícita pasa a explícito cuando se encuentra su definición. Ninguna tabla
  referencia a `symbol(id)`, así que el reemplazo no se propaga a otras filas.

## Verificación

- **`sodb_abi_test`** (`src/odin_writer/tests`, en C) escribe una base y la vuelve a leer con
  SQLite. Cubre:
  - nombres v1;
  - sobrecargas;
  - el mismo id para el mismo nombre;
  - los tres tipos de definición;
  - argumentos inválidos;
  - las ubicaciones de firma, calificador, local y rango atómico;
  - una llamada ambigua.

  Pasa en Windows. Si se revierte cualquiera de los dos arreglos del vendor, falla.
- **Odin sin cambios:** los 10 tests de `run_tests.ps1` pasan con el writer nuevo.
- **El core de Odin** (1.366 archivos, en lotes de 128), indexado con el writer anterior y con el
  nuevo:
  - Las bases son idénticas: 985.741 filas de nodos, aristas, ubicaciones y errores, comparadas
    ordenadas.
  - El tiempo no empeoró. En 5 rondas, el anterior tardó entre 29 y 49 s y el nuevo entre 25 y
    45 s. La máquina tenía ruido de carga.
- **`srctrl`** lee la base de prueba con los nombres decodificados (`C::f(int)`, `std::Vec`).

## Cómo correr la prueba

```sh
cmake -S src/odin_writer -B build/writer-abi -DSODB_WRITER_BUILD_TESTS=ON
cmake --build build/writer-abi --config Release
ctest --test-dir build/writer-abi -C Release --output-on-failure
```

## CI

El job nuevo `writer-abi` corre la prueba en Linux, Windows y macOS. Antes de este cambio, el writer
nunca se había compilado fuera de Windows, así que para Unix se agregaron dos cosas:

- `CMAKE_POSITION_INDEPENDENT_CODE`, porque la biblioteca estática se enlaza dentro de una
  compartida;
- `Threads` y `dl`, para el SQLite que trae incluido.

**No verificado:** Linux y macOS solo se van a comprobar en el CI.
