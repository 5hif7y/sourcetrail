## 2. Qué quedó hecho

### Odin

- Indexador nativo en `src/odin_indexer/main.odin`.
- **Batch**: varios `--source-file-path=` por proceso, caché de tablas por
  directorio, un open/commit por lote; el core agrupa de 128 en 128 con
  `%{SOURCE_FILE_PATH_ARGS}`.
- **Parser**: sin símbolos fantasma, no resueltas opt-in (`--unsolved`);
  atributos, directivas, `foreign ... ---`, `@(link_name)`, genéricos, `where`
  multilínea, resultados con nombre, loops, `switch x in`, `using` de campos,

  permite un checkout externo. Ya **no** hace falta el repo hermano.
- **Modo rápido** para DB temporales: `synchronous=OFF`, `foreign_keys=OFF`,
  `wal_autocheckpoint=0`, `cache_size=-65536`, `temp_store=MEMORY`.
  **No cambiar el journal mode**: el core usa WAL y su conexión abierta deja de
  ver los commits si se pone MEMORY (se observó 0 nodos).

## 5. Trampas

- No cambiar `journal_mode` en el modo rápido del writer (WAL del core).
- `sourcetrail_plugin_descriptor` es una **función**; hay que llamarla tras
  `GetProcAddress`/`dlsym`.
- Los efectos se disponen **antes** de cerrar la biblioteca; no cerrar antes.
- `---` se lexa como tres `-`; no buscar el token `"---"`.
- `skip_directive` consume hasta el newline (nivel superior);
  `skip_token_directive` es para declaraciones.
- Las no resueltas están apagadas por defecto; usar `--unsolved` para medirlas.
- Batch: el provider mapea cada archivo al mismo comando; consumir uno consume
  el lote.
- El árbol `neo-sourcetrail` está sucio a propósito; el limpio es
  `_work\modernized`.
